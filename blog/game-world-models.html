游戏世界模型究竟应该输出什么？

下一帧、状态、轨迹，还是可执行环境？读完 SIMA 2 与 Programmable World Model 后，我更关心一个世界能否记住规则、对象、资源、事件，以及行动造成的长期后果。

2026 · 10 · 11综述原文 ↗SIMA 2 ↗Programmable World Model ↗

我的判断是：游戏世界模型的核心输出不该只是一段看起来真实的视频，而应是一个可被行动改变、可被查询和验证、还能供 Agent 比较不同未来的世界状态。视频可以是它的观察层，不能代替它的世界。

SIMA 2 与 PWM，刚好位于闭环两侧

SIMA 2 是一个从屏幕观察、通过键鼠行动的通用 Agent。它把 Gemini 的推理能力接到 3D 游戏中，强调跨游戏理解指令、执行长任务和自我改进。它证明了游戏可以作为具身智能的训练场，也暴露出规划端的问题：官方明确写到，它仍受很长任务、目标验证和短记忆限制。

Programmable World Model 处理的是环境端。它把“世界状态如何演化”与“画面如何生成”拆开：轻量引擎保存显式状态并执行规则，带状态的 3D 定向框把结果编译成视频模型的条件，视频模型负责渲染。这让离开镜头的对象、角色生命值、关系和已经发生的事件不必全压在像素历史里。

这两篇不属于同一种模型。 SIMA 2 是使用环境的行动者；PWM 是给行动者提供可执行世界的环境框架。真正有研究价值的连接，是让 Agent 的行动进入世界状态，让世界的后果再成为 Agent 的观察、记忆与下一步规划依据。

三个维度，要用三组测试

01 · 视觉真实性

看单帧质量、时间连续性、几何稳定、对象身份和动作响应是否自然。FVD、感知距离与人工成对偏好可以测“像不像”，但不能证明规则正确。

02 · 机制正确性

固定初态，主动改变动作与条件，检查碰撞、伤害、资源消耗、事件触发和因果顺序是否符合规则。核心是干预后的状态转移，不是画面是否顺眼。

03 · 持久状态一致性

把对象移出镜头再返回，跨长时间、存档恢复和多次交互检查身份、位置、库存、任务进度、资源耗尽与不可逆事件有没有被忘记或改写。

因此，最有用的评测不该把三者压成一个总分。视觉层可以报告视频质量；机制层报告状态转移准确率、约束违反率、事件触发的 precision/recall；持久性则报告随时间增长的矛盾率、状态存活率与回访漂移。如果有权威游戏引擎，还应直接比对 health、collision、inventory 和 event trace。

1. “看起来真实”“规则正确”“状态长期一致”分别怎么测？

用独立测试集分别测。 视觉测试改变外观、镜头和光照；机制测试改变动作与规则条件，并保持外观尽量不变；持久性测试延长时间、遮挡对象、离开场景再回来。只有这样，才不会把漂亮画面误当成世界理解，也不会把一个短时正确的响应误当成长期一致。

从视频到可执行环境，是四种不同承诺

输出能回答什么主要缺口
下一帧 / 视频接下来大概会看到什么隐藏状态不可查询，多个看似合理的未来未必符合规则
结构化状态对象、属性、资源和关系怎样变化需要定义状态变量，也要解决从状态到真实观察的落差
动作条件轨迹执行一串动作后，状态与回报怎样演化误差会沿规划时域累积，需要不确定性与校准
可执行环境可以反事实干预、反复 rollout、验证规则并训练 Agent构建成本高，规则覆盖和模型偏差仍需独立检查

2. 一个模型生成视频，和一个模型能支持 Agent 规划，有什么区别？

视频生成器主要学习“什么画面看起来可能发生”；规划模型必须回答“如果采取动作 A 而不是 B，会分别发生什么”。后者需要动作可控、反事实可比、奖励或任务变量可读、长时状态稳定，并对预测不确定性诚实。最直接的检验不是视频分数，而是接入同一个 Agent 后，任务成功率、样本效率或规划 regret 是否改善。

哪些问题能迁移到机器人与物理仿真？

真正可迁移的是闭环中的问题：部分可观测下维护 belief state，对象离开视野后的持续存在，主动感知，动作条件预测，接触与事件造成的离散状态变化，资源和安全约束，以及长任务中的记忆、失败恢复和信用分配。

但游戏不能抹平现实差异。游戏可以廉价重置，并常有精确状态和明确规则；机器人面对传感噪声、控制延迟、接触动力学、安全代价和不可逆操作；物理仿真还要求守恒、数值稳定、参数辨识与跨尺度外推。游戏更适合先研究闭环结构与评测方法，再逐步加入这些现实约束。

3. 游戏环境的哪些问题可以迁移到机器人和物理仿真？

状态估计、因果干预、长时记忆、受约束规划和闭环误差可以迁移。 纯粹的画面逼真度迁移价值较弱；只有当视觉表征保留了接触、速度、物体身份、材料或资源等会改变行动结果的变量，它才开始成为机器人与物理世界模型的一部分。

我会研究模型与环境之间的闭环

只研究模型，很容易把问题缩成下一帧预测；只研究环境，又可能退回手工搭建。闭环把两者变成一个可检验的问题：Agent 提出行动，世界状态按规则演化，生成模型给出观察，验证器检查事实，Agent 再用这些后果规划。

Agent
提出行动与计划→显式世界状态
执行规则与事件→观察与验证
渲染、反馈、再规划

具体的研究切口可以是：一种同时保存规则、对象、资源、事件和长期后果的混合表征，能否在跨场景干预后保持一致，并让 Agent 的长时规划更好？ 这里可以把显式状态或物理引擎作为可查询的骨架，把学习模型用于感知、补全、动力学残差和生成式渲染。

4. 更想研究模型、环境，还是模型与环境之间的闭环？

闭环。 这条线最贴近物理仿真、世界模型、具身智能与 AI4S 的交叉点，也能形成清楚的实验：先测模型是否保存事实，再测环境是否执行规则，最后测这些能力是否真的帮助 Agent 完成长任务。

我想记住的研究判断

世界模型不是“会继续画画的相机”。它应当保存一个可以被行动改变的世界：对象有身份，资源会消耗，事件有先后，规则会约束转移，已经发生的后果不会因为镜头移开而消失。视觉真实性决定我们是否愿意相信眼前的观察；机制正确性决定行动是否有意义；持久状态一致性决定这个世界是否真的存在于时间里。
